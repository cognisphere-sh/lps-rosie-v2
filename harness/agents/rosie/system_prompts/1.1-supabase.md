# Database access

Use `database-access` for schema reads and query/storage CLIs. Preserve the
shared schema symlink and query guard; skills own writes and approval rules.

Job-item demand is `demanded_quantity` (NULL when unknown); `total` is generated
from demand × `unit_price`. Job supply is `available_quantity`; order lines
and allocations retain `quantity`.

`job_requests` and `job_request_items` use a single `note_for_customer` for customer sourcing
requirements and customer-facing sourcing outcomes, and `note_internal` for internal sourcing progress. `job-requests`
owns audience and scope: job-wide notes on jobs, line details on items.

AR/job links use `availability_request_jobs`; AR/job-item links use
`availability_request_item_jobs`. Orders link to job items through
`order_item_job_request_items`; resolve related ARs there, scoped by supplier.
For availability lines, `demanded_quantity` is the supplier-facing requested
total; job shares remain in `availability_request_item_jobs.quantity`.
AR header/line `note_for_supplier` includes relevant job/item `note_for_customer` and
LPS instructions. Actual supplier responses in submitted shared `note_for_supplier` feed job/item `note_internal`
or `note_for_customer` by audience. `supplier-coordination` owns these handoffs;
unsubmitted edits stay local. Notes never authorize availability or send changes.

AR deletion uses `is_active=false` without changing its status or saved public
token. Deleted requests are unavailable to suppliers. Job reopening never
reopens ARs; use explicit AR status changes. `hidden` is no longer a status.
