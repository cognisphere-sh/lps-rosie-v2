## What it should do

1. Keep short useful authored source decisions/updates/changes inline in a genuinely compact note field, with a discoverable icon opening full current and preserved prior sourcing detail. Do not reduce every populated note to an icon. Reclaim unnecessary width from the old repeated-text column while keeping useful context and the 44px interaction readable; merely adding an icon to the same wasteful strip is not done.
2. Use the current authored note honestly for inline context. An older long/multiline current note may have a visibly partial excerpt, but truncation is not semantic selection of 'critical' information. Do not infer, summarize, rank, strip, regenerate or rewrite content. Meaningful current authorship belongs to Rosie's approved standard, subject to the separate preservation reconciliation—not an AI summary or new UI-authored note policy.
3. Open sourcing content only by deliberate click/tap or Enter/Space. Keep an accessible “Sourcing note — internal” name, row context and visible focus, but no sourcing-text hover popup, native-title content dump or opening on mere focus. This restriction does not alter the separately approved hover/focus/touch original-customer-evidence disclosure.
4. In the activated panel, present authored important current items/decisions first, then complete source detail beneath. This is visual order based on the existing current note, not AI priority classification, an urgency score, a new attention flag or automatic issue detection. A blank current note must not acquire an invented attention item. Expansion must make the complete current note and the earlier full breakdown accessible from the note action, using exact retained evidence for this job/row. A popup showing only today's shortened note, or only the latest similarly brief history entry while hiding earlier full text, is insufficient. Distinguish current context from prior versions and match the exact job/line by stable identity, never plant name alone. A before-value's event time/actor describes the change that replaced it, NOT who originally authored it or when; label it honestly as before that recorded change. Display names are current read-time names unless contemporaneous names are actually retained. Do not invent missing authorship, original dates or historical plant names. Old quotes, supplier list prices, availability status and Chris-admin overrides must not be merged or shown as current supplier confirmation. Preserve the complete exact stored source text and supported links; long content must be readable within the viewport. A formatted Markdown presentation may normalize whitespace, so do not treat it alone as proof of lossless source access or irreversibly flatten/clip the retained text.
5. Prior evidence is read-only; current-note editing retains existing permissions/save/cancel/error behavior. Opening or reading detail never writes, clears, restores or copies notes. Edit only the intended current job/row note; cancel and Escape do not save the canceled draft. Avoid silent loss/wrong-row application on dismissal, scroll, keyboard movement or job changes. Provide usable close/Escape and predictable focus return without the table's Tab navigation skipping detail controls.
6. Be truthful about absence and loading. A blank current note does not prove no history; keep deliberate access to retained earlier detail when it exists. Clearly distinguish no current note, history loading, read failure and no retained history returned. An empty result does not prove a note never existed or distinguish absent/deleted records from no historical entries. Populated/empty cues must not imply unread, new, urgent, reviewed or confirmed. No fake counts/read tracking and no invented historical record.
7. Leave Shared Note visibly distinct with its current inline editor untouched. Original customer evidence stays unchanged. Job-wide selection, decisions and override provenance remain accessible once at their existing job scope; do not duplicate into every row, move/clear notes, or build a new evidence store. The row detail must not misrepresent job-wide authority as a supplier's answer.
8. Apply only to the reused internal Request items table in focused Jobs, expanded All Jobs and operator customer-detail request cards, preserving their different selection/deletion permissions. The operator's customer-detail page is not a customer portal. Do not blanket-apply to Orders, supplier portals, public availability, quotes, print or customer-facing output; internal notes must never be introduced there.
9. Preserve current operator changes, deliberate table ordering/resizing, horizontal scrolling, neighboring inline edits, totals, status meanings and job/list/scroll context. Coordinate serially with the separate focused Job table-density request rather than restoring an old table or resetting unrelated preferences.
