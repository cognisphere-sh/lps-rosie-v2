# All jobs (`/requests`)

All jobs is the one Jobs list. Its query, filters and page are retained in tab-scoped state. The server keeps the default order as parent `job_requests.updated_at DESC NULLS LAST`, then request `id DESC`; chat and line-item activity do not participate in that order. Created and Updated filters are rolling parent-request date windows, and the list remains server-paged.

## Mobile toolbar

The page resolves one `<900px` media query and passes that result to the toolbar and cards. SSR and unresolved hydration render a neutral, noninteractive toolbar placeholder; once resolved, exactly one branch mounts. Below 900px, the first toolbar row is a shrinking Search field beside one 44px icon-only **Filters** button. The row is non-wrapping and bounded to the page column. Expand all / Collapse all remains on the separate action row because it changes card disclosure rather than the result set. At 900px and above, only the established shared desktop toolbar and chip menus mount, including one copy of the Shell-owned actions.

Filters opens one body-portalled modal surface containing Status, Item status, Customer, Created and Updated. It edits the same state and therefore emits the same API query parameters as the desktop chips. Status starts with Sourcing, Quote Delivered, Closed won and Closed lost selected and Archived excluded. Restoring `lps.requests.visit.v1` migrates only the exact legacy display label **Quoted** to **Quote Delivered** before validation/deduplication, preserving the underlying `quoted` query value and saving only the canonical current label. The Filters active count is the number of filter groups that differ from that baseline; the four baseline status selections do not display as four active filters. While open, every body sibling is made inert and `aria-hidden` and body scrolling is locked, with each prior value restored exactly. Escape, pointer/touch backdrop and the explicit 44px Close control dismiss the surface; Tab and Shift+Tab stay inside. Each opening focuses Close once, while filter-state rerenders retain focus on the checkbox or radio just changed. Ordinary dismissal restores trigger focus. Crossing 899/900 unmounts the old surface/menu and its listeners and preserves selections. It transfers focus to the newly mounted Search only when the outgoing toolbar owned focus or its Filters surface was open; a connected control outside that toolbar or any other modal (Delete, availability and so on) keeps focus. Every transfer frame is cancelled or generation-invalidated by another crossing or unmount.

## Mobile request-card hierarchy and actions

A mobile card’s primary row is exactly **Company/Customer · Job name · Status · Rosie**. Identity values are trimmed first: Company/Customer uses nonblank company, then nonblank customer name, then **Unassigned customer**; Job name uses a nonblank name or `JR-<id>`. The two identity values are separate `min-w-0` flexible fields with one-line ellipses, and Job name remains the canonical `/jobs?jr=<id>` identity link with its full accessible name.

Status and the Rosie avatar are fixed, nonshrinking 44px accessible targets. The mobile status control deliberately removes the desktop dot/chevron chrome and draws deterministic compact tokens: **Src**, **QD**, **Won**, **Lost**, **Arc**. The full picker and accessible names remain **Sourcing**, **Quote Delivered**, **Closed won**, **Closed lost**, **Archived**; an unknown value uses up to three graphemes/initials and blank unknown is `?` with **Unknown status**, rather than inventing a status. Pointer, Enter or Space opens the unchanged 190px full-label picker within 8px viewport bounds; Tab can enter it, Escape returns focus to the trigger, and focus/outside pointer departure closes it. The token itself is never hidden or clipped.

Rosie still opens that request’s canonical `jr-<id>` thread. The quieter secondary row contains only the sole expansion chevron and JR reference. No created/updated date is shown or reformatted in the collapsed mobile summary. After the card expands, the existing nested **More details & notes** disclosure remains closed by default; only opening that disclosure mounts a labelled **Last updated** value from the exact parent `job_requests.updated_at`, using the established local-time date formatting, or **Not recorded** when missing. Closing it removes the value again. It never substitutes Created or parses notes. A future nullable Install Date belongs with Pickup/Delivery there, but no structured field/API exists yet, so those values stay blank and blocked. Desktop retains its established summary date as well as the shared details value. The primary row is non-wrapping and width-bounded at 320px, 390px and 480px, including long Unicode and blank identities and unknown statuses.

While a mobile card is collapsed, its plant-status summary shows only the exact **Pending** count; Available, Substituted and Unavailable remain hidden until expansion. Expanded mobile cards and desktop cards retain the established full four-status count strip and exact counts.

The chevron remains the only card expansion control. Collapsed mobile cards have no Actions control. An expanded mobile card adds one compact utility strip with the working **Delete job** action. Desktop retains its compact trash action in the card head.

Delete job opens the existing permanent-delete confirmation and uses the same `DELETE /api/requests/:id` path. Its authorization, related availability-request/answer deletion, history cleanup, result toast and focus-return behavior are unchanged. No Print, Copy or inactive utility is shown.
