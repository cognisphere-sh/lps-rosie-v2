Glossary

Every word this handbook uses for LPS's business, screens, data and agents, in alphabetical order. Each entry has a short definition, the name the system stores it under, and a link to the page that explains it in full.

BusinessTechnicalReference~20 min read (or look up one term)

How to use this glossary

Look a word up by its first letter. Each row has three parts:

  • Term: the word as you see it on screen or in conversation. Underneath, in code, is the name the database or software uses for it, where there is one. Engineers can skip to that. Business readers can ignore it.
  • What it means: one or two plain sentences.
  • See: the handbook page that covers it in depth.

Three small reference tables come after the A to Z list. They cover status labels and their stored values, short tokens and abbreviations, and older names you may still meet in the changelog or older notes.

Labels and stored values are not always the same

The screen label and the stored value sometimes differ on purpose. An availability request the supplier has submitted reads Completed but is stored as submitted. A job line that reads Can Order comes from a candidate stored as can_order, which the line and order vocabulary names need_to_order. When this glossary gives both, the label is what people say and the stored value is what the code checks.
